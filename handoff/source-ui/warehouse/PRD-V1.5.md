# 分门别类产品需求说明书 V1.5

开发目标：做一个珠宝商品分类工作台。员工上传一件商品的多张照片，系统给出分类建议，员工修改并确认，最后可以按形态、材料、大小、颜色、玉石特征和价格段找到商品。

第一阶段完成这个工作台；第二阶段接入相册、销售和照片风格三个系统，与分门别类形成四仓协作。本版将两阶段放在同一份文档内，供业务和技术共同评审。开发按本版拆任务；V1.4正文和四仓补充转为历史参考，不再要求开发同时对照三份文档。

## 1 开发范围

### 1.1 两阶段交付清单

| 阶段 | 必须交付 | 完成时能看到什么 |
|---|---|---|
| 第一阶段 | 商品上传、AI建议、人工审核、多维分类、条件筛选、历史、规则设置 | 不接其他仓，员工也能把商品整理好并查到 |
| 第二阶段 | 相册接入、销售资料接收、风格资格校验、回执、反馈与撤回 | 图组能进来，两个下游分别签收，出错知道卡在哪里 |

第一阶段支持手串、吊坠、裸石、配饰。手镯、戒指、项链、耳饰等可用“其他形态＋具体名称”登记，不强塞进四类。商品经营身份如旧料、改款成品另存，不和形态混用。

本次不做商城上架、订单、支付、库存扣减、客户聊天、自动发微信、自动报价。模型训练不是保存标签后自动发生的功能。真实风格生图需要第二阶段另配提供方、图片许可、预算和结果审核，不能用“风格资格通过”代替生图成功。

### 1.2 谁操作

| 角色 | 可以做什么 |
|---|---|
| 资料员 | 上传、填资料、改草稿、查看本商家的商品 |
| 审核员 | 上述操作，以及确认分类、退回补资料 |
| 负责人 | 确认价格依据、批准二阶段交接、维护分类标准 |
| 管理员 | 管理账号、字典和接口配置；没有业务角色时不能代替审核或经营批准 |

小团队允许同一个人兼任角色，但保存实际操作人和时间。所有查询、图片和写操作都限制在当前商家范围，不能只在页面上隐藏别人的商品。

## 2 用户操作流程

![两阶段业务流程](assets/01_两阶段业务流程.png)

### 2.1 第一阶段

1. 员工新建商品，输入或分配商品编号，上传同一件商品的多张照片。
2. 系统检查照片，给出AI建议。AI不可用时，员工仍可手填。
3. 员工在审核页选择主图，核对形态、材料、尺寸和颜色。
4. 适用玉石观察的商品，再填肉度等七项观察；有标准时选档位，无标准时只记观察。
5. 审核员点击“确认基础分类”。系统列出仍缺哪些尺寸、观察或分档标准。
6. 后续补齐细分资料；负责人独立确认价格依据，系统按已设置的价格段归类。缺这些资料不阻止第5步。
7. 员工在商品列表组合筛选，也能打开商品查看修改历史。

保存草稿、确认基础分类、完成全部细分是三件不同的事。具体按钮和判断条件见第6章。

### 2.2 第二阶段

相册送来图组后，进入同一个审核页。分类确认后，负责人分别批准销售资料或风格资格资料。系统发给对应仓，由对方保存并返回收据。销售和风格互不等待，也不互相代传商品事实。

## 4 上传与AI建议

### 4.1 商品和照片

商品编号在同一商家内唯一；新建时没有现成编号，可由系统生成内部编号。这里的内部编号不代表相册已经存在同一个编号。第二阶段必须显式关联相册编号，不凭相似照片猜同一件实物。

支持JPEG、PNG、HEIC，单张不超过20 MiB。一次上传可有多张照片，单张失败不影响其他照片。HEIC需要生成可预览图并保留原文件。照片必须能打开，选定的主图必须属于当前商品。没有合格主图不能确认基础分类。

上传时对比文件内容：同商品同图提示“已存在”，不重复加入；不同商品出现同图，提示人工核对，不自动合并。选错归属允许移图，但必须同时检查两个商品最新版本；移动成功后，两边需要重新确认。

每张照片保存文件身份、内容摘要、格式、所属商品、顺序、图片角色和是否排除。排除要填原因，历史保留；当前审核只使用未排除的图片。主图被排除后必须重选。

批量导入放在同一上传页的第二个入口：支持xlsx加图片，或包含这两者的ZIP。先预览商品编号与图片对应关系，确认后再创建商品。编号按文字保留前导0；一图对应多商品、缺图和找不到编号的图逐项列出，交人工处理，不自动猜归属。坏行不影响已明确的商品，重试不重复建商品；ZIP解压只允许本次临时目录，不执行宏和外部链接。

导入模板每行对应一张图：必填列“商品编号、图片文件名”，选填列“形态、材料、颜色、备注”。同商品多图重复填写编号；同编号的属性冲突先在预览里处理。文件名必须能唯一匹配上传目录中的图片，匹配不到或多个同名文件都列为异常，不默认取第一张。

### 4.2 AI输出和人工值

AI只提供建议：形态、材料、颜色、可见现象；有可靠标尺时可建议尺寸。重量和无标尺照片的毫米值不能凭空输出。尚无样例标准时，不要求AI给肉度、玉化度档位。

每项建议都显示“AI建议”，可展开来源图片和简短依据。员工采纳或修改后，保存为人工值，并记录确认人。原AI建议保留，方便比较；AI再次运行不能覆盖已确认人工值。

识别中显示进度；识别失败显示原因和“重试／手动填写”。不填假结果，也不阻断手工审核。模型返回字典以外的新名称先保留原文，交人工映射，不自动新增正式分类。

## 5 审核页要填的字段

### 5.1 基础属性

| 字段 | 输入方式 | 保存和检查规则 |
|---|---|---|
| 商品形态 | 手串、吊坠、裸石、配饰、其他、待确认 | 整件商品只有一个主形态；其他要填具体名称 |
| 材料 | 从材料字典选择，可先待确认 | 原有沉香、绿松石、南红、和田玉、彩宝、翡翠保留；可配置金属、木、绳及其他材料 |
| 材料依据 | 商家声明、凭证支持、信息不足 | 商家声明记录说明；凭证支持关联附件；不能自动变成鉴定结论 |
| 部件材料 | 添加主体、扣头、配珠、链绳等部件 | 主体和配件分开；不能因为有金属扣头就把整件归为金属 |
| 主色、次色 | 选择色词，次色可多选 | 保留来源图片；照片色差明显时显示冲突供人工处理 |
| 颜色分布 | 均匀、渐变、多色、局部分布、其他 | 描述如何分布，不直接判好坏 |
| 尺寸 | 随形态显示对应输入框 | 必须有数值、单位、测量对象和来源；允许先空着 |
| 主图 | 从本商品照片选择 | 只能一张，必须可读取且未排除 |

吊坠有扣头时，整件仍归吊坠；扣头单独卖才归配饰。整串作为手串卖，串内珠子属于部件，不再把整件同时归到裸石。混合材料无法确定主体时保留“混合待确认”，不能擅选占比最大的材料。

### 5.2 每种形态的尺寸框

| 形态 | 默认显示字段 | 需要分清的对象 |
|---|---|---|
| 手串 | 珠径最小值、最大值，珠数，内周长或适用腕围 | 珠径不是整串大小；单一珠径时最小值等于最大值 |
| 吊坠 | 主体长、宽、厚；含扣头整体长；孔径 | 主体尺寸和含扣头尺寸分开 |
| 裸石 | 长、宽、厚或直径；重量 | 重量单独带g或ct等单位，不从照片猜 |
| 配饰 | 根据子类型显示长度、直径、孔径、厚度等 | 孔径与外径分开；子类型由字典配置 |

尺寸来源选择“人工实测／商家资料／带标尺图像估测”。估测必须标明是估测和误差说明；无依据不填数值。范围内最小值不能大于最大值，实测长度和重量必须大于0。缺测量值用空值，不用0。

“大小段”由已确认尺寸和已发布的档表计算，例如某珠径段；真实分界由业务配置，不在本PRD编造。

### 5.3 玉石七项观察

材料和形态在设置里被标记为适用时，显示下表。不适用的商品不显示整块表单；无法确定适用性时显示“先确认材料”。每个维度都能先写观察，后选档位。

| 维度 | 员工看什么 | 页面记录什么 |
|---|---|---|
| 肉度 | 珠子内部结构的致密观感，结合透光及能否看到绳子 | 绳子清晰／模糊／不可辨／无绳不适用／条件不足；透光与结构描述、珠径、绳色、来源图 |
| 玉化度 | 玉石整体的透润、细腻和玉化感，按同材料样例比较 | 观察描述、参考样例、判断理由、档位；定义和档位需业务样例确认 |
| 光泽感 | 表面如何反光、反光强弱与柔和程度 | 表面反光描述、过曝等影响条件、来源图、档位 |
| 完整度 | 整体有没有缺口、断缺、缺失 | 缺失位置、描述、来源图；背面没图则写未观察 |
| 瑕疵度 | 局部裂纹疑似、坑点、划痕、杂点 | 问题类型、位置、范围、来源图及是否人工确认 |
| 工整度 | 孔位、形状、对称、边缘、加工或装配是否规整 | 适用项目的观察描述、来源图、档位 |
| 顺色度 | 单珠内部、同材料珠间或整串配色是否一致或协调 | 比较范围、单色／渐变／多色设计、观察、来源图、档位 |

肉度采用用户给出的业务定义；照片里的致密观感不等于测出了物理密度。无绳裸石不能因“看不见绳”被自动判高肉度。不同珠径、绳色或光照不能不加说明直接比较。

玉化度与光泽感分别保存和筛选，不相互自动填同档。完整度与瑕疵度涉及同一个缺口时，共用一条问题记录，不重复创建事实。本期不做综合品质分，因此不设计总分权重。异形和多色设计不能自动判差。

### 5.4 每个观察只需要一种操作方式

每项显示四部分：观察文字、来源图片／问题位置、确认状态、档位。状态只用“待确认／已确认／信息不足／不适用”；不适用和信息不足要说明原因。

档位下拉框来自该材料、形态和维度的已发布配置。没有配置时显示“待配置标准”，禁用选档但允许保存观察。档位为空与档位低不是一回事。

长文本允许语音辅助输入：支持时可把口述转成当前未保存表单，仍需员工查看后保存；不支持麦克风时正常打字。语音不能直接确认分类、发布规则、批准交接或报价。

点击“确认观察”只确认观察文字和依据；只有标准存在且审核员选定档位，才算这一项已分档。后端分别保存观察确认状态和grade_code，grade_code可以为空。

### 5.5 手串的单珠复核

手串审核页提供“单珠复核”入口。员工可以在原图上查看AI标记，选择某颗珠子，移动标记、补点、删除错误标记，并填写该珠材料及观察。位置确认和材料确认分别保存；确认整件材料不会自动确认所有珠子。

同一张图缩放或手机切换后，标记仍要落在同一颗珠子。完全遮挡的珠子不猜补；局部遮挡记录遮挡。图外点击不新建点。手串密集时可从旁边列表选珠子，不能要求手机上精准点中小圆点。

整串另填“观察了多少颗、多少颗未观察、差异说明”，同材料珠子可以分组记录。整串档位由审核员基于已配置的规则确认，不能取最好一颗代表整串。没有整串汇总标准时显示“待汇总标准”。

### 5.6 价格与价格段

价格区包括：币种、单颗／整件／重量单位等计价单位、价格类型、金额或上下限、价格依据、确认人和有效期。价格类型先支持商家提供价与内部建议区间；确认单独由负责人操作，不因审核员保存分类就自动批准。

系统用已确认价格匹配同商家、同材料、同形态、同计价单位的档表。区间只落在一个档内才显示该档；跨两个档显示“跨价格段”并保留上下限，不自动取中位数。单颗价和整串价不能混用，过期价显示待重新确认。

没有价格依据时显示“待补价格”，仍可保存和完成基础分类。这里不自动计算市场价值，也不生成对客报价。

## 6 按钮和分类进度

### 6.1 三个主要操作

| 按钮 | 前置检查 | 点击成功后 | 失败时 |
|---|---|---|---|
| 保存草稿 | 图片归属和字段格式合法 | 保存已填内容及新版本，保留待补项 | 定位错误字段；不吞掉当前编辑 |
| 确认基础分类 | 审核员；主图有效；形态已明确；主体材料有人工确认值和来源说明；图片归属冲突已处理 | 基础分类变为已确认，列出细分待补项 | 列出具体缺项，不能只提示“资料不全” |
| 退回补资料 | 审核员选择缺项并写说明 | 标记待补、记录原因，资料员能继续补填 | 未填退回原因时提示补原因 |

基础分类不强制所有尺寸、价格与七维档位齐全。它只表示已经弄清这是什么商品及材料按何种来源填写。材料仍为“信息不足”或“混合待确认”时，基础分类不能确认，但草稿可保存。

技术保存两个结果：基础审核是否已确认；细分分类还缺哪些必需项。细分进度由后台按设置自动计算，不给人工“强制完成”按钮。

### 6.2 什么时候显示全部细分完成

同时满足：基础已确认；当前规则要求的尺寸、颜色和适用观察已确认；必需档位有标准且已选定；设置要求价格段时有有效价格段；没有未处理的图片或字段冲突。

设置未要求的维度不阻断完成；不适用要有原因且经审核确认。未配置但被设置为必需的档位会显示“待配置标准”，不能假装完成。负责人能看到是缺员工资料还是缺业务标准。

已确认的照片、材料、尺寸、观察、档位或规则发生有效变更后，保留旧版本，新版重新审核；第二阶段对应旧交接也要过期或撤回。只改页面排序偏好不触发业务重审。

### 6.3 错误和多人编辑

草稿保存前带上打开页面时的版本号；服务器版本已变化时不覆盖别人的内容，提示“商品已被他人更新，请对比后再保存”。重复点击保存不新增两份相同版本。恢复历史生成一个新草稿，不删除后来的历史。

列表刷新失败显示“加载失败，请重试”，不能把失败当空列表；保存失败保留当前输入并明确未保存。离开未保存页面给出保存、放弃或留下三个选择。系统不承诺浏览器关掉后恢复未保存内容。

## 7 分类结果和搜索

![分类字段关系](assets/02_分类字段关系.png)

分类结果按字段显示：形态、材料及来源、尺寸及大小段、主次色、七项适用观察和档位、价格段、待补项。不要把全部内容拼成一段卖点文案后就丢掉结构字段。

商品列表按编号搜索；可组合筛选形态、材料、大小段、颜色、七项档位、价格段和待补状态。同一个字段选多个值表示满足任一，例如翡翠或和田玉；不同字段之间同时满足，例如手串且浅绿。空值不当低档或0分。

每行显示基础确认状态和细分待补摘要，打开可查看原始图片、AI建议、人工值、依据和历史。筛选只使用当前商家的当前有效版本，查看历史要显式进入历史页。

## 8 分类设置怎样做

设置按四个区域组织：材料与形态字典、玉石观察适用范围、观察档位与参考样例、尺寸段与价格段。普通资料员不能发布规则。

一个观察标准填写：适用材料、适用形态、维度名称、是否必需、档位代码和显示名、每档解释、参考样例、版本。材料和形态未匹配时不套用别的规则；负责人要能预览一件商品会显示哪些字段。

尺寸和价格档位填写数值上下限及适用单位。本版建议下限包含、上限不包含，最后一档可无上限；实际边界在业务发布档表时确认，区间不能重叠。混珠尺寸跨档显示“跨尺寸段”，不取平均数硬分档。

保存设置草稿不影响现有商品。点击发布前显示影响商品数；发布生成新版本，旧规则和旧分类保留，受影响商品标记“规则更新，待复核”，不能悄悄变成新档位。图片样例由业务提供；系统不自动抓取客户图充当标准。

## 9 第二阶段四仓合作

### 9.1 四仓各做什么

![四仓合作关系](assets/04_四仓合作关系.png)

| 仓 | 收到什么 | 做什么 | 给回什么 |
|---|---|---|---|
| 相册整理 | 员工的商品照片 | 按商品号组织图组 | 给分类仓图组、来源修订和图片 |
| 分门别类 | 相册图组 | 人工确认分类，按用途批准发送 | 两种资料包，以及本仓的交接记录 |
| 销售仓 | 销售资料包 | 独立保存，在内部审核台展示 | 收货回执、使用反馈 |
| 客户照片风格 | 风格资格资料及许可 | 核对商品、图片和用途资格 | 接受／拒绝及原因 |

销售侧实际接收项目、服务地址、代码版本和负责人要由联调时确认；历史名称有销售之旅、销售指导，不凭名称认定服务相同。商城不计在本次四仓中。

### 9.2 开发五条明确链路

| 链路 | 用户触发 | 系统必须完成 | 算成功的依据 |
|---|---|---|---|
| 相册到分类 | 相册提交同件商品图组 | 校验商家、编号、来源修订、图片内容；进入审核待办 | 分类仓有收件记录，实际图片能读取且内容摘要一致 |
| 分类到销售 | 负责人点“批准销售预览并交接” | 展示待发字段；从指定人工版本生成预览包；独立销售仓保存 | 对方自产收据有效，销售审核台能看到该版本 |
| 分类到风格 | 负责人点“校验风格资格” | 检查材料来源、图片和逐图转换许可；由风格仓决定 | 对方自产接受或拒绝回执；不是生图成功 |
| 销售反馈到分类 | 销售内部使用资料 | 送回使用事件和准确资料版本；去重保存 | 同一事件只记一次，不改变商品材料和价格 |
| 风格状态到分类 | 自动查询或接收通知 | 按原交接号回读并核验 | 更新对应交接，不拿旧回执替换新商品版本 |

销售与风格分别直接接收分类仓资料，不从彼此复制。两边分别批准，一边失败不阻断另一边已获批的交接。

### 9.3 传什么字段

共同必带：商家、商品编号、分类版本、图组摘要、交接编号、用途、合同版本及内容摘要。销售预览包另带已允许的尺寸、颜色、观察、材料来源性质、经营摘要与缺项；内部证据附件和客户聊天不传。

风格包另带获准图片、主图及逐图转换许可，不带价格、库存、客户资料和内部备注。照片传输按受控接口做，不能把电脑路径或永久外链当图片已送到；实际接收点必须读到图片字节并核对摘要。

照片更新、材料来源撤回、分类重审或用途许可失效后，旧资料不得继续用于新业务操作。已经签收的历史事实保留，再发更正或撤回通知并记录对方回执。

### 9.4 页面和异常

审核页新增销售、风格两张交接卡。每张卡显示：待补、待批准、待发送、待核对、已接收或被拒绝；同时显示资料有效／已过期／已撤回。收货状态与有效性分开，避免把已撤回写成从没收到。

只有收到正确接收方的回执且交接号、商家、包摘要一致，才显示已接收。请求超时先按原交接号查询；不能换新号反复发。相同包重发返回同一回执；相同号内容不同报冲突。两个服务重启后，任务和回执仍在。

技术建议沿用HTTP接口、数据库待发记录和后台任务，不要求为了联调先建一套新平台。待发记录与资料包一起保存，实际网络发送在保存完成后执行。各仓使用自己的收货记录，不直连对方业务表，也不能由本仓模拟器替对方签收。

### 9.5 本次第二阶段做到哪里

已查阅的本项目销售V3合同只允许内部预览，风格V3合同只允许资格校验。因此第二阶段的第一批验收先证明资料流、独立回执与反馈可靠；正式销售放行或真实生图要补双方支持的合同和配置。

真实生图扩展启用前，业务确认提供方、许可、预算与输出审核；技术增加任务编号、生成状态、产物文件和输入来源关联。生成图标记“生成”，与实拍分开存，不能拿来反推材料、瑕疵或价格。本版不声称现有代码已经实现这些功能。

## 11 开发用的数据和接口建议

本章给技术落表和拆接口用，属于建议字段名；如现有项目已有同义字段，做映射并复用。没有要求推倒重建数据库。

### 11.1 最少保存这些数据

| 数据 | 最少字段 |
|---|---|
| 商品 | id、tenant_id、product_code、version、form、其他形态名、经营身份、基础确认状态 |
| 图片 | asset_id、product_id、原文件摘要、预览图引用、类型、顺序、角色、排除原因 |
| 材料 | product_id、component_id、部件角色、material_code、来源类型、说明／附件引用、确认人时间 |
| 尺寸和颜色 | 字段代码、数值或范围、单位、对象、来源、人工状态；主次色、分布和来源图 |
| 七项观察 | dimension、scope、观察文字、来源图、状态、grade_code、rule_version；肉度等专有观察保留结构值 |
| 问题位置 | finding_id、asset_id、区域、类型、描述；完整度和瑕疵可引用同一条 |
| 价格 | 币种、计价单位、类型、金额或范围、依据、确认人时间、有效期、价格段结果 |

每条业务记录带商家归属；不得跨商品或商家引用图片、附件和收据。单珠标记以原图左上角为原点，矩形x、y、width、height保存为0到1的比例；宽高大于0且不能越界。缩放只改显示，HEIC预览或裁剪需要保留原图变换关系。

观察记录示例仅演示格式，不是实际识别或等级标准：

```json
{
  "dimension": "fleshiness",
  "scope": "bead-1",
  "observation": "内部绳子模糊可辨",
  "cord_visibility": "blurred",
  "source_asset_ids": ["demo-image-1"],
  "review_status": "confirmed",
  "grade_code": null,
  "rule_version": null
}
```

肉度英文代码是开发建议。示例表示员工确认了观察，但没有可用分档规则，所以档位为空；不能显示成已完成肉度分档。

### 11.2 第一阶段建议接口

下列是拟开发工作台接口，不声称项目已存在这些路由。最终地址可沿用团队约定，但行为要实现。

| 操作 | 建议接口 | 请求要点和成功返回 |
|---|---|---|
| 商品列表 | GET /v1/products | 编号、筛选条件、分页；返回商品摘要、待补项、下一页 |
| 新建商品 | POST /v1/products | 编号可空、草稿；返回商品id、编号、version |
| 上传照片 | POST /v1/products/{id}/images | 文件或受控上传引用；返回asset_id、预览和重复／失败结果 |
| 读取审核页 | GET /v1/products/{id}/review | 返回图片、AI建议、人工值、规则、当前version、待补项 |
| 保存草稿 | POST /v1/products/{id}/drafts | base_version、改动字段、request_id；返回新版和逐字段错误 |
| 确认基础分类 | POST /v1/products/{id}/confirm | base_version、request_id；返回基础状态和细分待补项 |
| 请求AI建议 | POST /v1/products/{id}/recognition-jobs | 图组版本；返回任务号；另用任务号查询结果 |
| 查看或恢复历史 | GET /v1/products/{id}/versions；POST /v1/products/{id}/restorations | 恢复传目标历史版本和当前base_version，生成新草稿 |
| 分类配置 | GET /v1/classification-settings；POST其drafts和publications子资源 | 读取／保存草稿／发布分开，发布需负责人权限 |

退回补资料和价格确认是独立写操作，分别记录缺项原因与经营批准；技术可放在商品资源下，不与confirm合成一个“全部通过”接口。恢复历史、发布配置等操作也要传当前版本和请求身份，避免重复或覆盖。

写请求中的request_id用于防止同一操作重复执行：同号同内容返回原结果；同号异内容返回冲突。version过旧返回409并提供服务器版本与变化字段；格式／缺项用422并给字段路径；无权限返回403或不可见资源404。登录身份、商家和操作人由服务器确定，不采用网页自填值。

第二阶段先核对现有相册、销售与风格合同，再给缺少字段做版本升级。不要把上面拟开发的工作台接口当作外部仓已有接口；具体双方地址、字段映射和正反样例在B1完成。

## 12 验收时照着操作

下表为需要执行的验收，不是当前已经通过的测试。使用虚构商品和合成照片，第一阶段至少覆盖手串、吊坠、裸石、配饰。

| 编号 | 操作 | 预期结果 |
|---|---|---|
| A01 | 四形态分别上传多图，故意放入一张坏图 | 成功图保留，坏图可重传；主图只能选本商品有效图 |
| A02 | 重复图、跨商品同图、xlsx前导0编号和缺图 | 同商品不重复；跨商品人工核对；编号保留，缺图逐项提示 |
| A03 | AI超时或返回新词，再手工修改 | 手填可继续，新词待映射；再次识别不覆盖人工值 |
| A04 | 带扣吊坠、单卖扣头、混合材料手串 | 主形态唯一，主体与配件材料分开 |
| A05 | 无标尺图，缺重量，尺寸上下限填反 | 不生成毫米或重量；反范围阻止保存并指出字段 |
| A06 | 有绳手串与无绳裸石分别填肉度 | 原始观察保留；无绳不自动判高肉度 |
| A07 | 高反光但内部未观察；七项无分档标准 | 光泽与玉化分别记录；允许存观察，档位为空 |
| A08 | 背面未拍、同一个缺口、多色或异形设计 | 未观察明确；缺口共用记录；设计不自动判差 |
| A09 | 手串补点删点、手机缩放，并用最好一颗代全串 | 标记不漂移；位置材料分开；整串须保留差异，不能自动取最好档 |
| A10 | 价格缺依据、跨段或单颗／整件单位不同 | 草稿和基础分类不被缺价卡住；细分待补明确；跨段不硬选 |
| A11 | 保存、确认基础分类、查看细分进度 | 三者分清；缺材料来源不能确认基础，缺档表不伪装细分完成 |
| A12 | 两人同时修改，重复保存，恢复旧版 | 旧版写入冲突；重复不多建；恢复新增草稿，历史仍在 |
| A13 | 多字段筛选，再切换商家或账号 | 同轴任选、跨轴同时满足；不看到别家数据和图片 |
| A14 | 发布新档表，再看旧已确认商品 | 旧版保留，受影响商品待复核，不静默改档 |
| B01 | 相册独立服务送图，重放、乱序、只送JSON不送图 | 首次与重复可查；旧图组不覆盖；媒体未到不算就绪 |
| B02 | 分类仓分别发往独立销售与风格服务 | 对方分别落账和回执；销售审核台可见；风格资格与生图分清 |
| B03 | 一端断线、重启、对方已收但回复丢失 | 另一端不受影响；原号查询恢复，不重复创建包 |
| B04 | 使用反馈重放、旧回执晚到、跨商家回执 | 不重复计数；只归原版本；越权或摘要错拒绝 |
| B05 | 签收后撤回材料来源或图片许可 | 停新使用和发送；旧收货事实保留；撤回有对方回执 |
| B06 | 检查风格资格接受与拒绝两种用例 | 两类结果均可追溯；不能只测拒绝就说完整正向链路通过 |

手机还要检查表单输入、软键盘、保存按钮和单珠选择；桌面要检查长表单滚动和未保存离开。备份恢复、上传限制、权限、图片访问与二阶段签名由技术纳入上线检查，必须保留实际执行结果，不能只交“全部通过”一句话。

## 13 业务只需要补这四项标准

| 待确认项 | 业务给什么 | 未确认前开发怎么做 |
|---|---|---|
| 哪些商品适用玉石观察 | 材料×形态，以及需要哪些维度 | 配置框架和基础表单先做；适用性未确认不乱套规则 |
| 七项观察如何分档 | 每档名称、解释、典型图和边界反例；整串如何汇总 | 先记观察和人工确认；下拉显示待配置，不编高低档 |
| 大小段和价格段 | 每种对象和单位的区间及边界归属、价格口径和有效期 | 数值、依据和档表编辑先做；不编真实分界 |
| 第二阶段实际对接方 | 四仓服务、负责人、支持合同；是否启用真实生图及其提供方预算 | 人工流程、接口适配和测试可做；外部能力未验证就标待联调 |
